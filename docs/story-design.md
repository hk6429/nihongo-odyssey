# 言葉旅記：英雄之旅故事設計

## 本次交付

`story.js` 提供三位角色、五座國度、二十五篇完整原創閱讀故事。每篇包含三段日中對照正文、白狐對話、兩個行動選項、一道三選一閱讀理解題、旅途獎勵，以及三位角色各自的反思。

故事素材與人物關係均為本次原創。N5～N1 是產品內部的漸進閱讀路線標籤，不代表文本已取得 JLPT 官方分級、字彙涵蓋率或題目認證；不得將二十五道理解題解讀為能力檢定成績。

本文件說明文字資料及預期互動契約。是否已在畫面完成選擇持久化、回聲與結局回收，仍需由介面實測確認；資料存在不代表互動已實作。

## 核心旅程

文字從五座國度消失。旅人從一張仍有微光的紙片出發，與白狐導師「白」尋找五枚言葉印。前半段以生活小事建立觀察、求助與回應的能力；後半段揭露，文字的消失源於守護者墨守與白曾把安靜誤當作安全。

旅人最後面對的抉擇，是是否接受一個永不爭執、卻也無法提出新需要的世界。結局讓各地共同參與文字的保存、查證與修正。旅人帶回日常的方法，村民也在旅人不在的日子裡成長。

英雄之旅的轉變不依靠擊敗某個天生邪惡的人。白與墨守必須承認後果、交出獨占決定權並參與修復；當事人保有不立即原諒、選擇參與方式與持續提出問題的空間。

## 角色與視覺

三位角色共走一條主線；`roleNotes` 呈現每個事件對選定角色的意義，避免換角色只換姓名。

| ID | 人物 | 起點 | 旅途轉變 | 歸返時的能力 |
| --- | --- | --- | --- | --- |
| `sora` | 空，藍衣旅人 | 急著跨出第一步，容易替別人決定 | 願意停下來、承認害怕、確認同行者 | 有勇氣行動，也讓別人能一起出發 |
| `akari` | 燈，朱衣記錄者 | 善於接住他人，容易忽略自己的需要 | 說出願望、尊重界線、不替人表態 | 能同理，也能清楚說不 |
| `ren` | 蓮，墨綠書生 | 擅長分析，期待找到完整答案 | 留意情境、當事人與尚未確定的部分 | 能查證，也允許答案繼續修正 |
| `shiro` | 白，常駐白狐導師 | 曾參與封閉森林，卻隱瞞過去 | 坦白、接受質疑、回到現場補救 | 從永遠帶路的人，成為能一起學習的同行者 |

整體視覺方向為日式國風潑墨與紙本留白。空、燈、蓮的人形立繪採頭部：身體約 1：1 的 Q 版比例，並用服裝主色、小冊子與行囊區分；白以白狐與墨色尾端維持辨識度。表情應能表現猶豫、傾聽、決心、後悔及安心。本文檔不宣稱立繪已產製。

## 資料契約

僅匯出 `roles`、`regions`、`episodes`，不含 HTML 或執行介面邏輯。

- `roles`: `{ id, name, title, description, trait }`；固定三位可選人物。
- `regions`: `{ id, name, subtitle, description, color }`；順序為 N5、N4、N3、N2、N1。
- `episodes`: 二十五筆。`id` 為 `N5-1` 格式；`level` 為國度 ID；`index` 為區內 0～4。
- `title`、`beat`、`summary`：標題、敘事功能、導讀。
- `paragraphs`: 至少三筆 `{ ja, zh }`；本版每篇三筆，共七十五組。
- `dialogue`: `{ speaker, ja, zh }` 陣列；本版均為 `shiro`，無須額外 NPC 頭像才能使用。
- `choices`: 每篇兩筆，ID 固定為 `observe` 與 `help`，但實際行動依事件不同。每筆都有 `{ id, label, result, echo, ending }`。
- `question`: `{ prompt, options, answer, explanation }`；`options` 為三個繁中選項，`answer` 為 0～2 的索引。
- `reward`: 印記或旅途物件的顯示名稱。
- `roleNotes`: `{ sora, akari, ren }`；顯示選定角色的觀點，不必在同一次閱讀顯示三份。

## 選擇如何留下影響

`observe` 和 `help` 都是有效的行動方向，不是善惡選項；前者偏向核對、記錄與保存，後者偏向邀請、協調與共同參與。它們不改變五國的主線順序，卻讓留下的社會習慣、物件、角色關係與結局敘述不同。

每次選擇必須存下篇章 ID 與選項 ID；重整後仍能讀回。資料欄位分成三層：

1. `result`：選定後即時呈現的具體回應，例如補好港口燈號表，或讓資深船員也願意提問。
2. `echo`：後續旅程可讀的影響，例如到了霧森先查路標的時間，或讓白因先前被傾聽的經驗而敢於坦白。可先收進旅人手札，在後續頁面或國度回顧顯示；以「這個選擇留下的回聲」呈現，不要當作本篇正文已發生的新事件。
3. `ending`：結局依實際選擇回收。例如保存燈號更新日期，或設立出航前的提問時間。每筆都有專屬句子，不能只依觀察／協助的總數套用一段通用結局。

N1-5 已寫明墨景會映出實際選擇。建議結局畫面按國度整理已選的 `ending`，再加上目前角色的 `roleNotes`。未讀或未選的篇章不可補上預設選項，避免冒充玩家做過的決定。選擇可以只存 ID，顯示時從本檔對應文字，避免不同版本存下重複全文。

例如 N4-4 的兩條路：

| 選擇 | 立即反應 | 旅途回聲 | 結局留下的事物 |
| --- | --- | --- | --- |
| 核對燈號 | 找出舊圖表缺漏並補上日期 | 進霧森先詢問路標年代與用途 | 港口保留版本與更新日期 |
| 邀大家提問 | 資深船員也承認還有不懂的地方 | 白知道坦白可以被聽完 | 船員會議保留提問時間 |

主線合流讓篇章規模可控；上述回應、回聲、結局與角色反思，則是必須實際呈現的差異。若畫面只改選項顏色、加分或顯示「已選擇」，尚未完成這份故事的互動契約。

## 漸進閱讀設計

| 區域 | 文本重點 | 理解題要求 |
| --- | --- | --- |
| N5 | 短句、具體物件、位置、簡單動作與問候 | 找出直接寫出的事實與原因 |
| N4 | 事件先後、條件、目的、說明與相互回應 | 連結行動與目的，分清訊號的意思 |
| N3 | 情境差異、時間條件、轉述、未知與修正 | 補回條件，理解行為改變的原因 |
| N2 | 對比、讓步、刪節造成的偏差與公共討論 | 比較原意和表述，辨認必要的補救 |
| N1 | 抽象抉擇、多方視角、制度與個人責任 | 理解目的與代價，統整跨篇成長 |

每題答案均可由本篇正文找到，不以文外常識、對角色的好惡或隱藏的「正確價值」判分。題目錯誤不應覆蓋玩家先前的敘事選擇；選擇偏好與閱讀理解是不同資料。

## 驗證與界線

本版以 Node 匯入資料，檢查三位角色、五區各五篇、二十五個唯一 ID、七十五組日中段落、五十組完整選擇、七十五則角色反思、所有閱讀題索引與必要欄位。這些是結構檢查，不等於日文母語審校、JLPT 分級認證、玩家實測或教學成效驗證。

交付仍需整合者確認：選擇能持久化，回聲與結局讀取的確是玩家所選，角色切換不會串用別人的資料，N1-5 的歸返不會因 N1-4 先取得第五印而被跳過，日中對照在手機可閱讀。
